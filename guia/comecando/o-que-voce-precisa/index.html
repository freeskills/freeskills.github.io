What you need to start O que você precisa para começar

A short list. The goal is to keep you from spending weeks preparing the environment before you create anything. Uma lista curta. O objetivo é evitar que você passe semanas preparando o ambiente antes de criar qualquer coisa.

Introdução

Dá para gastar um mês escolhendo teclado, tema do editor e dezenas de extensões, e ainda não ter um projeto na tela. Para este guia, “estar pronto” significa ter o mínimo que permite criar, errar e corrigir.

Prepare o necessário e comece a construir.

O que você vai aprender

  • Quais peças são realmente obrigatórias no começo.
  • O que pode esperar para depois.
  • Por que disposição para experimentar conta tanto quanto ferramenta.

Por que isso importa

Ferramentas demais no início viram desculpa para não começar. Você não precisa do setup perfeito. Precisa de um computador que rode um editor, um terminal e uma IA, e de tempo para usá-los de verdade.

O necessário

Um computador

Qualquer máquina razoável dos últimos anos serve: notebook ou desktop, Linux, macOS ou Windows. Não espere um equipamento novo para dar o primeiro passo. Se o computador abre um navegador e um editor, ele já entra no jogo.

Acesso à internet

As ferramentas de IA e boa parte da documentação vivem online. Uma conexão estável é suficiente. Você não precisa de um laboratório isolado nem de uma rede especial.

Um terminal

O terminal é a janela de texto onde você roda comandos: iniciar um projeto, usar Git, instalar algo, ver um erro. No macOS e no Linux ele já vem com o sistema. No Windows, o caminho mais confortável para desenvolvimento costuma ser o WSL, veremos isso em seguida.

Um editor de código

Escolha um editor e fique com ele por um tempo. Cursor e o fluxo do Claude Code são opções naturais se você vai trabalhar com IA no dia a dia. VS Code também serve. O importante é conseguir abrir uma pasta de projeto, editar arquivos e ver o que mudou.

Uma ferramenta de IA

Este guia usa o Claude como referência, no terminal, no editor ou no fluxo que você já tiver. O raciocínio vale para outras ferramentas parecidas. Sem uma IA no ambiente, você até consegue acompanhar o texto, mas perde a prática que o guia quer ensinar.

Disposição para experimentar

Você vai rodar comandos que ainda não memorizou. Vai ler mensagens de erro. Vai pedir à IA para explicar um arquivo. Isso faz parte. O ambiente só “clica” quando você usa, não quando assiste alguém usar.

Disposição para errar e corrigir

Código quebra. Prompts saem vagos. Uma alteração resolve uma coisa e estraga outra. O hábito útil não é evitar o erro. É parar, ler o que aconteceu, ajustar e tentar de novo. A IA ajuda nesse ciclo. Ela não tira o ciclo de você.

O que não precisa agora

Não monte uma lista enorme de ferramentas. Por enquanto, deixe de lado:

  • dezenas de extensões e temas;
  • vários editores “só para comparar”;
  • servidores, bancos e deploys avançados;
  • Skills, plugins e métodos mais estruturados, eles entram mais tarde neste guia.

Próximo passo

Com a lista mental pronta, o próximo conteúdo ajuda você a escolher o sistema em que vai trabalhar: Linux, macOS ou Windows.

Introduction

You can spend a month picking a keyboard, an editor theme, and dozens of extensions, and still have no project on screen. In this guide, “ready” means the minimum that lets you create, fail, and fix.

Prepare what you need and start building.

What you will learn

  • Which pieces are actually required at the beginning.
  • What can wait.
  • Why a willingness to experiment matters as much as the tool.

Why this matters

Too many tools at the start become an excuse not to start. You don't need a perfect setup. You need a computer that runs an editor, a terminal, and an AI, and time to actually use them.

What you need

A computer

Any reasonable machine from recent years will do: laptop or desktop, Linux, macOS, or Windows. Don't wait for new hardware. If it opens a browser and an editor, it is in the game.

Internet access

AI tools and most documentation live online. A stable connection is enough. You don't need a special lab network.

A terminal

The terminal is the text window where you run commands: start a project, use Git, install something, read an error. On macOS and Linux it ships with the system. On Windows, the most comfortable path for development is usually WSL, we cover that next.

A code editor

Pick one editor and stay with it for a while. Cursor and the Claude Code flow are natural if AI will sit next to your code. VS Code also works. What matters is opening a project folder, editing files, and seeing what changed.

An AI tool

This guide uses Claude as the reference, in the terminal, in the editor, or in the flow you already have. The same thinking applies to similar tools. Without AI in the environment you can still follow the text, but you miss the practice the guide wants to teach.

Willingness to experiment

You will run commands you have not memorized. You will read error messages. You will ask the AI to explain a file. That is part of it. The environment only “clicks” when you use it.

Willingness to be wrong and fix it

Code breaks. Prompts come out vague. A change fixes one thing and breaks another. The useful habit is not avoiding errors. It is stopping, reading what happened, adjusting, and trying again. AI helps that loop. It does not take the loop away.

What you don't need yet

Don't build a huge tool list. For now, skip:

  • dozens of extensions and themes;
  • several editors “just to compare”;
  • servers, databases, and advanced deploys;
  • Skills, plugins, and more structured methods, they come later in this guide.

Next step

With that short list in mind, the next page helps you choose the system you will work in: Linux, macOS, or Windows.
