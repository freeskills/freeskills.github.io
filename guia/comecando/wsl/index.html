Linux on Windows with WSL Linux no Windows com WSL

WSL is the simplest way to have a real Linux next to Windows, without switching computers or giving up the programs you already use. WSL é a forma mais simples de ter um Linux de verdade ao lado do Windows, sem trocar de computador e sem abandonar os programas que você já usa.

Introdução

WSL significa Windows Subsystem for Linux. Em termos práticos: o Windows passa a oferecer um ambiente Linux em que você abre um terminal, instala ferramentas e trabalha em projetos como faria em um computador Linux.

Esta página explica o conceito e quando vale a pena. Não é um passo a passo longo de instalação, a documentação oficial da Microsoft cobre isso com cuidado e muda com as versões do Windows.

O que você vai aprender

  • O que o WSL é, e o que ele não é.
  • Por que ele ajuda quem desenvolve no Windows.
  • Quando utilizar e o que fazer depois de decidir usá-lo.

Por que isso importa

Sem o WSL, muita gente no Windows vive traduzindo comandos, caminhos de pasta e instruções feitas para Linux. Com o WSL, o projeto, o Git e a IA no terminal passam a falar a mesma língua dos exemplos que você vai encontrar neste guia e na maior parte da documentação de desenvolvimento.

O que é

Pense no WSL como um Linux que mora dentro do Windows. Você continua abrindo o navegador, o e-mail e o editor no Windows. Quando for desenvolver, abre um terminal Linux (muitas vezes o Ubuntu) e trabalha ali.

Não é uma máquina virtual pesada no sentido antigo, nem uma “janela que finge ser Linux”. É um ambiente Linux real, com sistema de arquivos, pacotes e comandos próprios, integrado ao Windows.

Por que pode ser útil

  • Você usa as mesmas ferramentas que tutoriais de Linux e macOS mostram.
  • Git, Node, Python, Docker e CLIs de IA costumam ter um caminho mais direto.
  • O editor no Windows (por exemplo o Cursor) consegue abrir a pasta do projeto que vive no Linux.
  • Você não precisa formatar o computador nem abandonar o Windows no dia a dia.

Como ele permite ferramentas Linux no Windows

Depois de instalado, o WSL oferece uma distribuição Linux, o Ubuntu é a escolha mais comum para começar. Dentro dela você instala pacotes com o gerenciador do Linux, clona repositórios e roda o projeto.

O Windows continua acessível. Arquivos podem ser vistos dos dois lados, mas o hábito saudável é guardar os projetos dentro do Linux (a pasta home do WSL) e abri-los no editor a partir daí. Assim você evita lentidão e diferenças estranhas de permissão.

Exemplo de uso no dia a dia

Você abre o terminal Ubuntu, entra na pasta ~/projetos, cria ou clona um repositório e pede à IA para trabalhar nessa pasta. O Windows continua aberto do outro lado, só o trabalho de código acontece no Linux.

Quando utilizar

Use WSL se você:

  • desenvolve no Windows e quer acompanhar exemplos no estilo Unix;
  • vai usar ferramentas de terminal (Git, CLIs, agentes de IA);
  • prefere não dual-boot nem trocar de sistema só para programar.

Pode adiar o WSL se você:

  • já está no Linux ou no macOS;
  • só quer ler este módulo agora e instalar depois;
  • já tem um fluxo no Windows nativo que funciona e entende as diferenças.

Como instalar, em linhas gerais

No Windows atual, o caminho oficial começa no terminal do Windows com um comando do próprio sistema e segue o assistente da distribuição. Confira sempre o guia atual: Install WSL na documentação da Microsoft.

Depois de instalar, abra o Ubuntu (ou a distro que você escolheu), crie seu usuário e só então avance para Git, editor e pastas de projeto.

Próximo passo

Com o sistema escolhido (Linux, macOS ou Windows com WSL), vamos montar as peças básicas do ambiente: terminal, Git, editor e um lugar para os projetos.

Introduction

WSL means Windows Subsystem for Linux. In practice: Windows offers a Linux environment where you open a terminal, install tools, and work on projects the way you would on a Linux machine.

This page explains the idea and when it is worth it. It is not a long install walkthrough, Microsoft's official docs cover that carefully and change with Windows versions.

What you will learn

  • What WSL is, and what it is not.
  • Why it helps people who develop on Windows.
  • When to use it and what to do after you decide.

Why this matters

Without WSL, many people on Windows spend their time translating commands, folder paths, and instructions written for Linux. With WSL, the project, Git, and the terminal AI speak the same language as the examples in this guide and most development docs.

What it is

Think of WSL as a Linux that lives inside Windows. You still open the browser, email, and editor on Windows. When you develop, you open a Linux terminal (often Ubuntu) and work there.

It is not a heavy old-school virtual machine, and it is not a window pretending to be Linux. It is a real Linux environment, with its own filesystem, packages, and commands, integrated with Windows.

Why it can help

  • You use the same tools Linux and macOS tutorials show.
  • Git, Node, Python, Docker, and AI CLIs usually have a more direct path.
  • The Windows editor (Cursor, for example) can open the project folder that lives in Linux.
  • You don't need to reformat the computer or abandon Windows for daily life.

How it lets you use Linux tools on Windows

After install, WSL gives you a Linux distribution, Ubuntu is the most common starting point. Inside it you install packages with the Linux manager, clone repositories, and run the project.

Windows stays reachable. Files can be seen from both sides, but the healthy habit is to keep projects inside Linux (your WSL home folder) and open them in the editor from there. That avoids slowness and odd permission issues.

Everyday example

You open the Ubuntu terminal, go to ~/projetos, create or clone a repo, and ask the AI to work in that folder. Windows stays open on the other side, only the coding work happens in Linux.

When to use it

Use WSL if you:

  • develop on Windows and want Unix-style examples;
  • will use terminal tools (Git, CLIs, AI agents);
  • prefer not to dual-boot or switch OS just to program.

You can postpone WSL if you:

  • are already on Linux or macOS;
  • only want to read this module now and install later;
  • already have a native Windows flow that works and you understand the differences.

How to install, in outline

On current Windows, the official path starts in the Windows terminal with a system command and follows the distro wizard. Always check the current guide: Install WSL in Microsoft's documentation.

After install, open Ubuntu (or the distro you chose), create your user, and only then move on to Git, editor, and project folders.

Next step

With the system chosen (Linux, macOS, or Windows with WSL) we assemble the basic pieces: terminal, Git, editor, and a place for projects.
