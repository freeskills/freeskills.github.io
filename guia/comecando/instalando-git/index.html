1.6

Installing Git Instalando o Git

With Git installed and a first commit saved, you can change code with AI and still know what changed and how to go back. Com o Git instalado e um primeiro commit salvo, você pode mudar código com IA e ainda saber o que mudou e como voltar atrás.

Introdução

Sem Git, cada alteração da IA é um salto no escuro: você não tem um ponto seguro para comparar. Com Git, o histórico vira a rede de segurança do módulo seguinte, quando o primeiro projeto começa de verdade.

Esta página é prática. O objetivo é terminar com o Git instalado, nome e e-mail configurados, e um repositório de teste com pelo menos um commit.

O que você vai aprender

  • Como verificar se o Git já está no sistema.
  • Como instalar no Linux, no macOS e no WSL.
  • Como configurar nome e e-mail uma vez.
  • Como criar um repositório, salvar um commit e ver o diff.

Por que isso importa

No próximo módulo você vai criar e modificar arquivos com ajuda da IA. Sem um histórico, “desfazer” vira adivinhar. Com um commit limpo, o diff mostra exatamente o que a IA mudou, e você decide o que fica.

1. Confira se já está instalado

Abra o terminal (no Windows, use o WSL) e rode:

Verificar

git --version

Se aparecer algo como git version 2.x.x, o Git já está pronto. Pule a instalação e vá para a configuração.

2. Instalar

Escolha o caminho do seu sistema. No Windows, instale dentro do WSL, não no PowerShell do Windows, para os comandos deste guia baterem com o restante do material.

Linux (Debian / Ubuntu) e WSL

sudo apt update
sudo apt install -y git

Em Fedora ou RHEL, o equivalente costuma ser sudo dnf install -y git. Em Arch: sudo pacman -S git.

macOS

A forma mais simples é instalar as ferramentas de linha de comando da Apple (trazem o Git): 

xcode-select --install

Se você já usa Homebrew, também funciona brew install git. Depois, rode de novo git --version.

Referência oficial

Se o seu sistema for diferente, use o guia atual: git-scm.com/downloads.

3. Configurar nome e e-mail

Faça isso uma vez por máquina. Os commits vão carregar esses dados. Use o nome que você quer ver no histórico e um e-mail real seu: 

git config --global user.name "Seu Nome"
git config --global user.email "voce@email.com"

Para conferir:

git config --global --list

4. Primeiro repositório e primeiro commit

Crie uma pasta de teste dentro de ~/projetos (ou a pasta mãe que você escolheu) e grave um ponto inicial: 

mkdir -p ~/projetos/teste-git
cd ~/projetos/teste-git
git init
echo "# teste" > README.md
git add README.md
git commit -m "Primeiro commit"
git status
git log --oneline

Se git status disser que não há nada pendente e git log mostrar o commit, o básico está pronto.

5. Ver o que mudou

Edite o README.md, salve, e compare com o último commit: 

git diff

Esse comando é o que você vai usar o tempo todo quando a IA alterar arquivos: olhar o diff antes de aceitar o resultado.

Neste módulo, Git local basta. Conta no GitHub, SSH keys, branches e pull requests podem esperar o primeiro projeto real.

Checklist antes do próximo conteúdo

  • git --version responde sem erro.
  • user.name e user.email estão definidos.
  • Existe pelo menos um commit em uma pasta de teste.
  • Você sabe abrir o terminal na pasta do projeto.

Introduction

Without Git, every AI change is a leap in the dark: you have no safe point to compare against. With Git, history becomes the safety net for the next module, when the first project starts for real.

This page is practical. The goal is to finish with Git installed, name and email configured, and a test repository with at least one commit.

What you will learn

  • How to check whether Git is already on the system.
  • How to install it on Linux, macOS, and WSL.
  • How to set name and email once.
  • How to create a repository, save a commit, and read a diff.

Why this matters

In the next module you will create and change files with AI help. Without history, “undo” becomes guesswork. With a clean commit, the diff shows exactly what the AI changed, and you decide what stays.

1. Check if it is already installed

Open the terminal (on Windows, use WSL) and run:

Check

git --version

If you see something like git version 2.x.x, Git is ready. Skip install and go to configuration.

2. Install

Pick the path for your system. On Windows, install inside WSL, not in Windows PowerShell, so the commands in this guide match the rest of the material.

Linux (Debian / Ubuntu) and WSL

sudo apt update
sudo apt install -y git

On Fedora or RHEL, the usual equivalent is sudo dnf install -y git. On Arch: sudo pacman -S git.

macOS

The simplest path is Apple's command line tools (they include Git): 

xcode-select --install

If you already use Homebrew, brew install git also works. Then run git --version again.

Official reference

If your system is different, use the current guide: git-scm.com/downloads.

3. Set name and email

Do this once per machine. Commits will carry that identity. Use the name you want in history and a real email of yours: 

git config --global user.name "Your Name"
git config --global user.email "you@email.com"

To verify:

git config --global --list

4. First repository and first commit

Create a test folder inside ~/projetos (or the parent folder you chose) and save an initial point: 

mkdir -p ~/projetos/teste-git
cd ~/projetos/teste-git
git init
echo "# teste" > README.md
git add README.md
git commit -m "First commit"
git status
git log --oneline

If git status says nothing is pending and git log shows the commit, the basics are ready.

5. See what changed

Edit README.md, save, and compare with the last commit: 

git diff

This is the command you will use constantly when AI changes files: read the diff before you accept the result.

In this module, local Git is enough. A GitHub account, SSH keys, branches, and pull requests can wait for the first real project.

Checklist before the next lesson

  • git --version responds without error.
  • user.name and user.email are set.
  • There is at least one commit in a test folder.
  • You know how to open the terminal in the project folder.
