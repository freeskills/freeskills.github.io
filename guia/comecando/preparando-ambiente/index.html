1.5

Setting up your environment Preparando o ambiente

Four pieces are enough at the start: a terminal you know how to open, Git installed, an editor, and a fixed place for projects. Quatro peças bastam no começo: um terminal que você sabe abrir, Git instalado, um editor e um lugar fixo para os projetos.

Introdução

Ambiente não é uma coleção de extensões. É o conjunto mínimo que permite criar um projeto, ver o que mudou, desfazer um erro e pedir ajuda à IA com contexto. Quanto mais simples no início, mais rápido você chega no trabalho de verdade.

O que você vai aprender

  • Para que serve o terminal no dia a dia.
  • Por que o Git entra cedo, mesmo em projetos sozinhos.
  • Como escolher um editor sem se perder em plugins.
  • Uma forma simples de organizar pastas.

Por que isso importa

Quando a IA gera ou altera arquivos, alguém precisa saber onde isso aconteceu. O terminal mostra comandos e erros. O Git mostra o histórico. O editor mostra o código. A pasta do projeto é o chão comum das três coisas.

Terminal

Abra o terminal do seu sistema (ou o do WSL, se estiver no Windows). Pratique só o básico:

  • pwd: em que pasta você está;
  • ls: o que existe nessa pasta;
  • cd: entrar em outra pasta;
  • mkdir: criar uma pasta.

Você não precisa memorizar um livro de comandos. Precisa se sentir à vontade para entrar na pasta do projeto e rodar o que a documentação (ou a IA) pedir, lendo a resposta na tela.

Git

Git registra versões do seu código. Mesmo trabalhando sozinho, ele é a rede de segurança: se uma alteração da IA estragar algo, você consegue ver o diff e voltar atrás.

Neste módulo você só precisa das ideias básicas:

  • repositório: a pasta do projeto com histórico;
  • commit: um ponto salvo, com uma mensagem curta;
  • diff: o que mudou desde o último ponto salvo.

A instalação, a configuração e o primeiro commit ficam na próxima página: Instalando o Git. Ainda não precisa dominar branches, rebase ou fluxos de time.

Editor

Use um editor que abra a pasta inteira do projeto, não um arquivo solto. Cursor é uma escolha natural se a IA vai viver ao lado do código. VS Code e o fluxo do Claude Code também servem.

Instale o essencial do próprio editor e pare. Destaques de sintaxe já vêm prontos. Extensões de formatação e de Git podem esperar até o primeiro projeto pedir por elas.

Organização dos projetos

Crie uma pasta única e reutilize-a. Por exemplo: ~/projetos no Linux, no macOS ou no WSL. Cada sistema novo vira uma subpasta: ~/projetos/lista-tarefas, ~/projetos/meu-site.

Evite deixar projetos na área de trabalho, em downloads ou misturados com documentos pessoais. Quando você (ou a IA) precisar “abrir o projeto”, o caminho deve ser óbvio.

Exemplo de estrutura

~/projetos/
 lista-tarefas/
 meu-site/
 experimentos/

Uma pasta mãe. Um diretório por ideia. Nada de dezenas de clones espalhados pelo disco.

Ferramentas básicas

Além de terminal, Git e editor, só acrescente o que o próximo projeto exigir. No começo isso costuma ser:

  • um navegador atualizado, para ver interfaces web;
  • a runtime que o projeto pedir (por exemplo Node ou Python), quando chegar a hora;
  • a ferramenta de IA, no próximo conteúdo.

Não instale “o kit completo de um time sênior” preventivamente. Cada ferramenta a mais é uma coisa para atualizar, configurar e esquecer.

Próximo passo

Com a mesa arrumada, o próximo conteúdo instala o Git de verdade: conferir a versão, configurar nome e e-mail e gravar o primeiro commit. Depois disso, a IA entra no ambiente.

Introduction

An environment is not a pile of extensions. It is the minimum set that lets you create a project, see what changed, undo a mistake, and ask the AI for help with context. The simpler it is at the start, the faster you get to real work.

What you will learn

  • What the terminal is for day to day.
  • Why Git belongs early, even on solo projects.
  • How to pick an editor without getting lost in plugins.
  • A simple way to organize folders.

Why this matters

When AI generates or changes files, someone needs to know where that happened. The terminal shows commands and errors. Git shows history. The editor shows the code. The project folder is the common ground for all three.

Terminal

Open your system terminal (or WSL, on Windows). Practice only the basics:

  • pwd: which folder you are in;
  • ls: what is in that folder;
  • cd: enter another folder;
  • mkdir: create a folder.

You don't need to memorize a book of commands. You need to feel comfortable entering the project folder and running what the docs (or the AI) ask, while you read the output.

Git

Git records versions of your code. Even working alone, it is the safety net: if an AI change breaks something, you can see the diff and go back.

In this module you only need the basic ideas:

  • repository: the project folder with history;
  • commit: a saved point with a short message;
  • diff: what changed since the last saved point.

Install steps, configuration, and the first commit are on the next page: Installing Git. You still don't need branches, rebase, or team workflows.

Editor

Use an editor that opens the whole project folder, not a single file. Cursor is a natural fit if AI will live next to the code. VS Code and the Claude Code flow also work.

Install the editor's essentials and stop. Syntax highlighting is already there. Formatting and Git extensions can wait until the first project asks for them.

Organizing projects

Create one parent folder and reuse it. For example: ~/projetos on Linux, macOS, or WSL. Each new system becomes a subfolder: ~/projetos/lista-tarefas, ~/projetos/meu-site.

Avoid leaving projects on the desktop, in downloads, or mixed with personal documents. When you (or the AI) need to “open the project”, the path should be obvious.

Example layout

~/projetos/
 lista-tarefas/
 meu-site/
 experimentos/

One parent folder. One directory per idea. No clones scattered across the disk.

Basic tools

Besides terminal, Git, and editor, add only what the next project requires. At the start that is usually:

  • an up-to-date browser, to see web UIs;
  • the runtime the project asks for (Node or Python, for example), when the time comes;
  • the AI tool, in the next lesson.

Don't install “the full senior-team kit” in advance. Each extra tool is something to update, configure, and forget.

Next step

With the desk cleared, the next lesson installs Git for real: check the version, set name and email, and save the first commit. After that, AI joins the environment.
