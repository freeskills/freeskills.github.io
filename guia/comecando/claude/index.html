1.7

Installing and using Claude Instalando e utilizando o Claude

AI stops being an isolated browser tab and starts working inside the project, with the files, the terminal, and the changes in view. A IA deixa de ser uma aba isolada no navegador e passa a trabalhar dentro do projeto, com os arquivos, o terminal e as mudanças à vista.

Introdução

Neste guia, “usar o Claude” significa ter um assistente que enxerga a pasta do projeto. Isso é diferente de colar um pedaço de código num chat genérico e torcer para a resposta encaixar. O valor está no contexto: arquivos reais, erros reais, histórico real.

O mesmo hábito vale se você estiver no Claude Code, no Cursor ou em outra ferramenta parecida. A marca muda; o jeito de trabalhar não precisa mudar.

O que você vai aprender

  • O que significa colocar a IA no ambiente de desenvolvimento.
  • Como trabalhar dentro de um projeto, não em um vácuo.
  • Como dar contexto, revisar alterações e avançar aos poucos.

Por que isso importa

Sem contexto, a IA inventa uma estrutura que não é a sua. Com contexto demais e um pedido gigante, ela tenta resolver o produto inteiro e você perde o fio. O ponto útil fica no meio: pasta certa, pedido pequeno, revisão obrigatória.

Instalação, em alto nível

Siga o caminho oficial da ferramenta que você escolheu e pare quando conseguir abrir o projeto e conversar com a IA ali. Não otimize o setup além disso neste módulo.

  • Claude Code: instale o CLI e autentique com sua conta. A referência oficial está em docs.anthropic.com.
  • Cursor: instale o editor, abra a pasta do projeto e use o agente no próprio workspace.

Se mais tarde você quiser o marketplace FreeSkills (plugins como o SDD), a instalação está na página inicial. Isso é opcional agora. Skills, plugins e SDD ficam para módulos futuros deste guia.

Trabalhar dentro de um projeto

Sempre comece pela pasta. Abra ~/projetos/meu-site, não a home, não um arquivo solto. Peça à IA para ler o que já existe antes de criar coisa nova.

Exemplo

Estamos na pasta deste projeto. Antes de mudar qualquer
arquivo, descreva o que já existe e qual parece ser o
objetivo do código.

Se a pasta está vazia, diga isso com clareza e defina um objetivo pequeno. “Quero uma página estática que lista três itens” é melhor do que “cria meu produto”.

Dar contexto

Contexto útil costuma ser:

  • o que você quer que aconteça, em uma ou duas frases;
  • o que já tentou e o que quebrou;
  • limites: “não mude o CSS ainda”, “só o arquivo X”;
  • o público: “é o meu primeiro projeto”, “explique as mudanças”.

Contexto inútil costuma ser um romance, um dump de dez arquivos sem pergunta, ou um “faz igual aos grandes sistemas que você conhece”. Prefira apontar o problema e a próxima fatia.

Analisar alterações

Toda vez que a IA mexer em arquivos, trate o resultado como proposta, não como fato consumado:

  • leia o diff no Git ou no próprio editor;
  • rode o projeto, se já existir um comando para isso;
  • pergunte o que não ficou claro, “por que este arquivo foi criado?”;
  • peça para desfazer ou reduzir o escopo se a mudança passou do combinado.

Se você não entende a alteração, ainda não terminou. Pedir uma explicação faz parte do trabalho, não é perda de tempo.

Trabalhar progressivamente

Um bom ciclo cabe em uma sessão curta: um objetivo, uma mudança, um teste, uma decisão. Depois o próximo objetivo. Resistir ao impulso de “já que estamos aqui, faz o resto” é o que mantém o projeto compreensível.

A IA é parte do ambiente, como o Git e o editor. Ela não é o ambiente inteiro, e não é a dona do repositório.

Próximo passo

Com a ferramenta no lugar, o último conteúdo deste módulo fecha o hábito mais importante: o fluxo de trabalho. É ele que impede o famoso “cria um sistema completo para mim”.

Introduction

In this guide, “using Claude” means having an assistant that can see the project folder. That is different from pasting a snippet into a generic chat and hoping the answer fits. The value is context: real files, real errors, real history.

The same habit applies if you are in Claude Code, Cursor, or a similar tool. The brand changes; the way of working does not have to.

What you will learn

  • What it means to put AI in the development environment.
  • How to work inside a project, not in a vacuum.
  • How to give context, review changes, and move in small steps.

Why this matters

Without context, the AI invents a structure that is not yours. With too much context and a giant request, it tries to solve the whole product and you lose the thread. The useful point is in the middle: the right folder, a small ask, a mandatory review.

Install, at a high level

Follow the official path for the tool you chose and stop when you can open the project and talk to the AI there. Don't optimize the setup beyond that in this module.

  • Claude Code: install the CLI and sign in. Official reference: docs.anthropic.com.
  • Cursor: install the editor, open the project folder, and use the agent in that workspace.

If you later want the FreeSkills marketplace (plugins such as SDD), install is on the home page. That is optional now. Skills, plugins, and SDD wait for later modules.

Work inside a project

Always start from the folder. Open ~/projetos/meu-site, not home, not a loose file. Ask the AI to read what already exists before creating something new.

Example

We are in this project's folder. Before changing any
file, describe what already exists and what the code
seems to be for.

If the folder is empty, say so clearly and define a small goal. “I want a static page that lists three items” is better than “build my product”.

Give context

Useful context is usually:

  • what you want to happen, in one or two sentences;
  • what you already tried and what broke;
  • limits: “don't change CSS yet”, “only file X”;
  • the audience: “this is my first project”, “explain the changes”.

Useless context is a novel, a dump of ten files with no question, or “make it like the big systems you know”. Point at the problem and the next slice instead.

Review the changes

Every time the AI touches files, treat the result as a proposal, not a done deal:

  • read the diff in Git or in the editor;
  • run the project, if there is already a command for that;
  • ask about anything unclear, “why was this file created?”;
  • ask to undo or shrink the scope if the change went past what you agreed.

If you don't understand the change, you are not done. Asking for an explanation is part of the work.

Work progressively

A good cycle fits a short session: one goal, one change, one test, one decision. Then the next goal. Resisting “while we're here, do the rest” is what keeps the project understandable.

AI is part of the environment, like Git and the editor. It is not the whole environment, and it does not own the repository.

Next step

With the tool in place, the last lesson in this module covers the most important habit: the working loop. That is what stops the famous “build a complete system for me”.
