1.8

How to build software with AI Como trabalhar com IA para desenvolver software

This is the central habit of the guide. Without it, the rest becomes a shortcut. With it, every later module gets easier. Este é o hábito central do guia. Sem ele, o resto vira atalho. Com ele, cada módulo seguinte fica mais fácil.

Introdução

O pedido mais comum (e o menos útil) é alguma variação de:

Crie um sistema completo para mim.

A IA aceita. Gera pastas, telas, nomes e regras que você não pediu. No fim você tem um programa que parece produto e se comporta como caixa-preta. O fluxo abaixo existe para evitar isso. Ele ainda não é um método formal de especificações. É a base mental. Métodos mais estruturados entram em módulos futuros.

O que você vai aprender

  • Um ciclo de sete passos para qualquer tarefa pequena.
  • Por que cada etapa existe.
  • Exemplos de pedidos fracos e pedidos que funcionam.

Por que isso importa

Software cresce por decisões. Se a IA toma todas de uma vez, você não sabe quais foram. Se você toma uma de cada vez, a IA vira acelerador: escreve o pedaço, você verifica, o projeto continua seu.

O fluxo

  1. 1Entenda o problema
  2. 2Defina o objetivo
  3. 3Peça uma análise ou plano
  4. 4Implemente uma pequena parte
  5. 5Teste
  6. 6Analise o resultado
  7. 7Continue evoluindo

1. Entenda o problema

Antes de qualquer código, responda: quem sofre com isso, o que essa pessoa tenta fazer e o que acontece hoje. Se você não consegue explicar o problema em voz alta, a IA também não vai “adivinhar certo”.

Exemplo

“Eu esqueço as tarefas da semana e acabo anotando em três lugares diferentes. Quero um único lugar, no navegador, para marcar o que já fiz.”

2. Defina o objetivo

Transforme o problema em um recorte. Não o produto dos sonhos: a próxima fatia visível. Um objetivo bom cabe em uma frase e tem um critério de pronto.

Objetivo fraco

“Quero um app de produtividade com login, nuvem e mobile.”

Objetivo útil

“Uma página local com uma lista. Eu consigo adicionar uma tarefa e marcá-la como feita. Ainda sem conta, sem banco e sem publicar.”

3. Peça uma análise ou plano

Peça à IA para pensar antes de escrever arquivos. “Quais arquivos isso precisa? O que pode dar errado? Qual é o menor caminho?” Se o plano vier grande demais, recorte: “faça só o item 1”. 

Não implemente ainda. Em até cinco passos, proponha o
menor caminho para uma página local com lista de tarefas.
Diga o que fica de fora nesta etapa.

4. Implemente uma pequena parte

Autorize só o próximo pedaço. Um arquivo, uma tela, um comando. Peça para a IA explicar o que vai mudar. Se ela criar cinco pastas sem você ter pedido, pare e reduza o escopo.

5. Teste

Rode no seu computador. Clique. Digite. Leia o erro no terminal. “Funcionou no chat” não conta. Se você não sabe como testar, peça exatamente isso: “como eu abro isso no navegador e o que eu deveria ver?”

6. Analise o resultado

Compare o que saiu com o objetivo. Ficou simples demais? Ótimo. Ficou diferente do combinado? Pergunte por quê. Tem um pedaço que você não entende? Peça um tour pelo arquivo, linha a linha se for preciso.

Aqui o Git ajuda: o diff é o mapa do que aconteceu de verdade.

7. Continue evoluindo

Só depois do pedaço atual estar compreendido e testado você pede o seguinte: persistir a lista, melhorar o visual, publicar. Cada volta no ciclo é um commit mental, e, de preferência, um commit de verdade.

O anti-padrão

Evite pedidos deste tipo:

  • “Cria um sistema completo de imóveis com login, pagamento e painel.”
  • “Faz igual ao Notion, mas para o meu caso.”
  • “Aplica as melhores práticas”, sem dizer quais nem em qual arquivo.

Eles empurram a IA para inventar um produto. Você herda as decisões sem ter participado delas.

Um ciclo inteiro, resumido

Exemplo curto

  1. Problema: esqueço o que preciso comprar.
  2. Objetivo: uma página com itens e um botão de marcar.
  3. Plano: um index.html, sem servidor.
  4. Implementação: só essa página.
  5. Teste: abrir no navegador e marcar um item.
  6. Análise: o item some ao recarregar. Ok, persistência fica para depois.
  7. Evolução: próximo pedido, um só: lembrar os itens no navegador.

O que vem depois deste módulo

Você já tem o mapa: ambiente, ferramenta e jeito de trabalhar. Os próximos módulos deste guia (ainda a publicar) usam esse ciclo em um primeiro projeto, depois em um sistema maior, e só então em Skills e especificações.

Até lá, pratique o fluxo em qualquer ideia pequena. Se quiser explorar o marketplace FreeSkills, comece pela instalação ou pelo catálogo de plugins. Não é obrigatório para fechar este módulo.

Introduction

The most common (and least useful) request is some version of:

Build a complete system for me.

The AI will accept. It generates folders, screens, names, and rules you never asked for. You end up with a program that looks like a product and behaves like a black box. The loop below exists to avoid that. It is not a formal spec method yet. It is the mental base. More structured methods come in later modules.

What you will learn

  • A seven-step cycle for any small task.
  • Why each step exists.
  • Examples of weak asks and asks that work.

Why this matters

Software grows through decisions. If the AI takes them all at once, you don't know which ones were made. If you take them one at a time, AI becomes an accelerator: it writes the slice, you check, the project stays yours.

The loop

  1. 1Understand the problem
  2. 2Define the goal
  3. 3Ask for an analysis or plan
  4. 4Implement a small slice
  5. 5Test
  6. 6Review the result
  7. 7Keep evolving

1. Understand the problem

Before any code, answer: who is hurting, what that person is trying to do, and what happens today. If you cannot explain the problem out loud, the AI will not “guess it right” either.

Example

“I forget weekly tasks and end up writing them in three places. I want one place, in the browser, to check off what I already did.”

2. Define the goal

Turn the problem into a slice. Not the dream product: the next visible piece. A good goal fits in one sentence and has a done criterion.

Weak goal

“I want a productivity app with login, cloud, and mobile.”

Useful goal

“A local page with a list. I can add a task and mark it done. Still no account, no database, no publish.”

3. Ask for an analysis or plan

Ask the AI to think before writing files. “Which files does this need? What can go wrong? What is the smallest path?” If the plan is too big, cut it: “do item 1 only”. 

Don't implement yet. In up to five steps, propose the
smallest path to a local page with a task list.
Say what is out of scope for this stage.

4. Implement a small slice

Authorize only the next piece. One file, one screen, one command. Ask the AI to explain what will change. If it creates five folders you did not ask for, stop and shrink the scope.

5. Test

Run it on your computer. Click. Type. Read the terminal error. “It worked in the chat” does not count. If you don't know how to test, ask exactly that: “how do I open this in the browser and what should I see?”

6. Review the result

Compare what came out with the goal. Too simple? Good. Different from what you agreed? Ask why. A piece you don't understand? Ask for a tour of the file, line by line if needed.

Git helps here: the diff is the map of what actually happened.

7. Keep evolving

Only after the current slice is understood and tested do you ask for the next: persist the list, improve the look, publish. Each loop is a mental commit, and, preferably, a real commit.

The anti-pattern

Avoid asks like:

  • “Build a complete real-estate system with login, payments, and an admin panel.”
  • “Make it like Notion, but for my case.”
  • “Apply best practices”, without saying which or in which file.

They push the AI to invent a product. You inherit the decisions without having made them.

A full cycle, short

Short example

  1. Problem: I forget what I need to buy.
  2. Goal: a page with items and a mark-done button.
  3. Plan: one index.html, no server.
  4. Implementation: that page only.
  5. Test: open in the browser and mark an item.
  6. Review: the item vanishes on reload. Ok, persistence waits.
  7. Evolution: next ask, one only: remember items in the browser.

What comes after this module

You already have the map: environment, tool, and way of working. Later modules of this guide (still to publish) use this cycle on a first project, then on a larger system, and only then on Skills and specifications.

Until then, practice the loop on any small idea. If you want to explore the FreeSkills marketplace, start with install or the plugin catalog. It is not required to finish this module.

Next step
