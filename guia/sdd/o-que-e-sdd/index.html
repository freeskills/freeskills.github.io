6.1

What SDD is O que é SDD

Specification Driven Development: agree what the admin area is, then implement a slice. Specification Driven Development: combine o que é a área administrativa, depois implemente uma fatia.

Introdução

Até aqui você pediu fatias e revisou no navegador. SDD acrescenta um passo no meio: a spec viva. A área administrativa da Marina (listar, cadastrar, editar, remover imóveis) tem atores, senha, persistência e o que o comprador não pode ver. Sem spec, a IA inventa um CRM.

SDD não apaga Skills. A Skill continua dizendo o visual. A spec diz o comportamento do admin. Cadastrar estoque não volta para o chat.

O que você vai aprender

  • A diferença entre Skill, decisoes.md e spec.
  • Por que a área administrativa é o exemplo (não um CRM).
  • O ciclo: DNA → spec → fatia → Definition of Done.

Por que isso importa

Feature com mais de um ator (comprador no site público, Marina no admin) é onde o prompt solto mente. Spec deixa os dois visíveis.

O que SDD não pede agora

  • Não é reescrever o site em outro framework.
  • Não é especificar a vida da imobiliária.
  • Não é pular o navegador. Done continua sendo URL + teste manual.

O plugin SDD do FreeSkills traz protocolos e .specs/. Você ainda instala na próxima lição. Aqui o hábito importa mais que a pasta.

Checklist

  • Você distingue Skill (como) de spec (o quê).
  • O exemplo daqui até o fim do guia é a área admin, não “o sistema todo”.

Próximo passo

Instale o plugin SDD no mesmo marketplace que você já adicionou.

Introduction

Until now you asked for slices and reviewed in the browser. SDD adds a step in the middle: a living spec. Marina’s admin area (list, add, edit, remove listings) has actors, a password, persistence, and what the buyer must not see. Without a spec the AI invents a CRM.

SDD does not erase Skills. The Skill still states the look. The spec states admin behavior. Adding inventory does not go back to the chat.

What you will learn

  • The difference between a Skill, decisoes.md, and a spec.
  • Why the admin area is the example (not a CRM).
  • The loop: DNA → spec → slice → Definition of Done.

Why this matters

A feature with more than one actor (buyer on the public site, Marina in the admin) is where a loose prompt lies. A spec makes both visible.

What SDD does not ask for now

  • Not a rewrite in another framework.
  • Not a spec of the whole brokerage.
  • Not skipping the browser. Done is still a URL + a manual test.

The FreeSkills SDD plugin brings protocols and .specs/. You install it in the next lesson. Here the habit matters more than the folder.

Checklist

  • You can tell a Skill (how) from a spec (what).
  • The example through the end of the guide is the admin area, not “the whole system”.

Next step

Install the SDD plugin from the marketplace you already added.
