6.4

Specify the admin area Especificar a área administrativa

Definition of Ready: the spec is small enough to build in one sitting. Definition of Ready: a spec pequena o bastante para fazer numa sentada.

Introdução

A spec do admin é o contrato. Se ela pedir CRM ou login social, você recusa: o DNA disse que não. Se ela omitir “remover”, a Marina fica presa a imóveis fantasma.

O que você vai aprender

  • Lista, cadastro, edição, exclusão e quem acessa.
  • Definition of Ready e Definition of Done.
  • Aprovar a spec antes de qualquer HTML novo.

Por que isso importa

Implementar sem spec neste ponto desfaz o módulo. O código tem que caber no texto que você aprovou.

Pedido

Prompt

DNA do site da Marina Alves está no repo. Skill marina-imovel vale só para o visual.

Escreva a spec da feature "Área administrativa de imóveis" (ainda sem implementar):

Pronto para implementar quando:
- Só a Marina acessa (/admin). Senha simples neste recorte; não é segurança de produção.
- Ela lista os imóveis do estoque (JSON).
- Ela cadastra um imóvel (titulo, bairro, quartos, preco, resumo, destaque).
- Ela edita e remove um existente.
- O catálogo público reflete a mudança depois de gravar.
- Comprador não vê o admin no menu.
- Não é CRM, não é multi-usuário, não é portal tipo ZAP.

Inclua Definition of Done:
- Senha errada: erro visível, sem entrar.
- Cadastro válido aparece na lista admin e no catálogo público.
- Remover some dos dois.
- Teste manual desses três caminhos.

Não gere HTML ainda. Quero a spec no .specs/ para eu ler e aprovar.
  1. 1Leia a spec em voz alta.
  2. 2Corte o que passou do DNA.
  3. 3Só então a próxima lição gera o admin.

Checklist

  • A spec está no repo e você leu.
  • Há um caminho feliz (cadastrar) e um erro (senha errada).
  • Done inclui o imóvel no catálogo público, não só “arquivo criado”.
