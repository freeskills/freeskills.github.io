Publishing our first project Publicando nosso primeiro projeto

The HTML is local. The domain is yours (or you know how to get one). Now pick how the files go online. O HTML está local. O domínio é seu (ou você já sabe como registrar). Agora escolha como os arquivos vão ao ar.

Introdução

Até aqui o site vive na sua máquina. Publicar é o momento em que outra pessoa (ou você, no celular) abre uma URL e vê o mesmo resultado.

Há duas formas neste módulo. Cada uma tem a própria página, com o passo a passo. Não misture as duas agora: escolha uma e termine o primeiro publish.

O que você vai aprender

  • O que preparar no projeto antes de enviar arquivos.
  • Quando a hospedagem compartilhada basta.
  • Quando um servidor VPS faz mais sentido.

Por que isso importa

Um site só na pasta ~/projetos ainda é rascunho. No ar, você aprende com feedback real: link no WhatsApp, teste no 4G, typo que só aparece longe do editor.

Também importa não misturar as ferramentas. HTML estático não pede a mesma estrutura de um sistema com banco, autenticação e deploy contínuo. Use o caminho simples agora. Reserve a estrutura mínima (VPS + Beway) para o que vem depois no curso.

1. Projeto local pronto

  • index.html na raiz da pasta do site.
  • CSS, JS e imagens com caminhos relativos.
  • Você já abriu a página no navegador local e gostou do resultado.
  • Opcional e recomendado: um commit limpo no Git.

Conferir

cd ~/projetos/meu-primeiro-site
ls
# deve aparecer index.html (e o CSS/JS que você usa)

2. Preparação para o deploy

Envie só o que o navegador precisa. Não suba node_modules, backups ou arquivos soltos da home. O index.html deve ficar na pasta pública do site (às vezes chamada public_html ou www).

Dica: se o CSS “sumir” depois do deploy, quase sempre o caminho no HTML apontava para um lugar que não foi enviado. Caminhos relativos resolvem a maior parte dos sustos.

3. Escolha uma forma

As duas colocam o HTML no ar. Elas não pedem o mesmo investimento agora. O detalhe de cada uma está na página seguinte.

Hospedagem compartilhada Painel, gerenciador de arquivos, HTML no ar. O caminho certo para este módulo. Servidor VPS Linux só seu e Beway: fácil de publicar, até 3 sites grátis e certificado automático.

Se o projeto ainda é só HTML, comece pela hospedagem compartilhada. A página do VPS existe para você conhecer o próximo degrau, não para travar o primeiro publish.

Checklist

  • Projeto local com index.html na raiz.
  • Domínio registrado ou, no mínimo, entendido.
  • Você sabe que o passo a passo de cada deploy está numa página separada.

Próximo passo

Abra a lição de hospedagem compartilhada e publique o site. Se você já tem (ou quer) um servidor próprio, pule para a lição de VPS.

Introduction

Until now the site lives on your machine. Publishing is the moment someone else (or you, on a phone) opens a URL and sees the same result.

There are two paths in this module. Each one has its own page, with the steps. Do not mix them now: pick one and finish the first publish.

What you will learn

  • What to prepare in the project before you upload files.
  • When shared hosting is enough.
  • When a VPS server makes more sense.

Why this matters

A site that only lives in ~/projetos is still a draft. Online, you learn from real feedback: a WhatsApp link, a test on mobile data, a typo that only shows up away from the editor.

It also matters not to mix the tools. Static HTML does not ask for the same setup as a system with a database, auth, and a serious deploy. Use the simple path now. Keep the minimum structure (VPS + Beway) for what comes later in the course.

1. Local project ready

  • index.html at the root of the site folder.
  • CSS, JS, and images with relative paths.
  • You already opened the page in a local browser and liked the result.
  • Optional and recommended: a clean Git commit.

Check

cd ~/projetos/meu-primeiro-site
ls
# you should see index.html (and the CSS/JS you use)

2. Prepare for deploy

Upload only what the browser needs. Do not send node_modules, backups, or random home-folder files. index.html should sit in the site's public folder (sometimes called public_html or www).

Tip: if CSS “disappears” after deploy, the HTML path almost always pointed somewhere that was not uploaded. Relative paths fix most of those scares.

3. Pick one path

Both put the HTML online. They do not ask for the same investment right now. The details live on the next pages.

Shared hosting Panel, file manager, HTML online. The right path for this module. VPS server Your own Linux and Beway: easy to publish, up to 3 free sites, automatic certificate.

If the project is still just HTML, start with shared hosting. The VPS page is here so you know the next step, not so the first publish gets stuck.

Checklist

  • Local project with index.html at the root.
  • A domain registered, or at least understood.
  • You know each deploy path has its own page.

Next step

Open the shared hosting lesson and publish the site. If you already have (or want) your own server, jump to the VPS lesson.
