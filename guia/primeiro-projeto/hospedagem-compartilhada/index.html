Shared hosting Hospedagem compartilhada

Rent space on a server that is already set up. Upload the files. Open the domain. Alugue um espaço num servidor que já está configurado. Envie os arquivos. Abra o domínio.

Introdução

Para este primeiro site HTML, você não precisa de um servidor próprio nem da Beway. Basta uma hospedagem compartilhada e enviar os arquivos pelo gerenciador de arquivos do painel (ou por FTP, se preferir).

Você aluga um pedaço de um servidor que já tem painel, pasta pública e, na maior parte dos casos, um jeito simples de apontar o domínio.

O que você vai aprender

  • Como enviar o HTML pelo gerenciador de arquivos.
  • Onde o index.html precisa ficar.
  • Como ligar o domínio à hospedagem.
  • Como validar a URL depois do envio.

Por que isso importa

Um site HTML é um conjunto de arquivos. Quem recebe esses arquivos e os entrega no navegador já resolve o primeiro publish. Não é necessário VPS. Não é necessário instalar a Beway.

Passo a passo

  1. 1Escolha uma hospedagem compartilhada (qualquer uma com painel e gerenciador de arquivos)
  2. 2Abra o gerenciador de arquivos e entre na pasta pública do site (public_html ou www)
  3. 3Envie index.html, CSS, JS e imagens. Só o que o navegador precisa.
  4. 4No registrador, aponte o domínio para a hospedagem (nameservers do provedor ou registro A)
  5. 5Abra o domínio no navegador e confira o resultado

O domínio nesta forma

A hospedagem quase sempre entrega nameservers (algo como ns1.seuprovedor.com) ou um IP. Você cola isso no painel do registrador, o da lição de domínios. A propagação pode levar minutos ou algumas horas. Enquanto isso, muitos painéis também dão um endereço temporário só para testar os arquivos.

Se o CSS “sumir” depois do envio, o caminho no HTML quase sempre apontava para um arquivo que não foi enviado. Caminhos relativos resolvem a maior parte dos sustos.

Validar o site publicado

  • Abra a URL em uma aba anônima.
  • Confira título, textos, links e o CSS.
  • Teste no celular (ou nas ferramentas de dispositivo do navegador).
  • Se algo falhar, corrija localmente, envie de novo e compare.

Quando estiver estável, celebre com um commit do tipo “versão publicada” e guarde a URL. Esse é o seu primeiro software acessível na internet.

Checklist

  • Arquivos na pasta pública, com index.html no lugar certo.
  • Domínio apontado (ou endereço temporário do painel funcionando).
  • A URL abre e mostra o mesmo site que você viu localmente.
  • Você sabe republicar depois de uma correção.

Introduction

For this first HTML site, you do not need your own server or Beway. Shared hosting and a file upload through the panel's file manager (or FTP, if you prefer) are enough.

You rent a slice of a server that already has a panel, a public folder, and, in most cases, a simple way to point the domain.

What you will learn

  • How to upload the HTML with the file manager.
  • Where index.html needs to sit.
  • How to attach the domain to the host.
  • How to validate the URL after the upload.

Why this matters

An HTML site is a set of files. Whoever receives those files and serves them to the browser already solves the first publish. You do not need a VPS. You do not need to install Beway.

Step by step

  1. 1Choose a shared host (any one with a panel and a file manager)
  2. 2Open the file manager and go into the site's public folder (public_html or www)
  3. 3Upload index.html, CSS, JS, and images. Only what the browser needs.
  4. 4At the registrar, point the domain at the host (the provider's nameservers or an A record)
  5. 5Open the domain in the browser and check the result

The domain on this path

The host almost always gives you nameservers (something like ns1.yourhost.com) or an IP. You paste that into the registrar panel from the domain lesson. Propagation can take minutes or a few hours. Meanwhile, many panels also give a temporary address just to test the files.

If CSS “disappears” after the upload, the HTML path almost always pointed at a file that was not sent. Relative paths fix most of those scares.

Validate the published site

  • Open the URL in a private window.
  • Check title, copy, links, and CSS.
  • Test on a phone (or the browser device tools).
  • If something fails, fix locally, upload again, and compare.

When it is stable, celebrate with a commit like “published version” and keep the URL. That is your first piece of software reachable on the internet.

Checklist

  • Files in the public folder, with index.html in the right place.
  • Domain pointed (or the panel's temporary address working).
  • The URL opens and shows the same site you saw locally.
  • You know how to republish after a fix.

Next step

The other way to publish is a VPS: a Linux box of your own and, later in the course, Beway. Worth knowing now, even if you do not buy one this week.
