2.1

Building our first site with AI Criando nosso primeiro site com IA

Empty folder, static HTML, and the basic loop: ask, review, improve. Pasta vazia, HTML estático e o ciclo básico: pedir, analisar, melhorar.

Introdução

Neste módulo você constrói software de verdade, ainda sem Skills e sem SDD. A ideia é sentir o processo direto: explicar o que quer, olhar o que a IA gerou, pedir mudanças e melhorar aos poucos.

O projeto é um site HTML estático. Começa em pasta vazia. Termina com arquivos que você abre no navegador e entende.

O que você vai aprender

  • Como abrir um projeto vazio e pedir a estrutura inicial.
  • Como analisar HTML, CSS e (se houver) JavaScript gerados.
  • Como melhorar o site em passos pequenos, sem reinventar tudo.

Por que isso importa

Se o primeiro pedido for “faz um site completo e profissional”, a IA entrega um pacote grande e você perde o fio. Um site pequeno ensina o hábito certo: escopo curto, resultado visível, revisão obrigatória.

Preparar a pasta

No terminal, dentro de ~/projetos (ou a pasta mãe que você já usa):

Terminal

mkdir -p ~/projetos/meu-primeiro-site
cd ~/projetos/meu-primeiro-site
git init

Abra essa pasta no Cursor, no Claude Code ou no editor que você escolheu. Confirme que está vazia (só o .git, se já inicializou o repositório).

O primeiro pedido

Fale o contexto e o objetivo. Não peça o produto da sua vida. Peça uma página compreensível.

Prompt

Estamos numa pasta vazia. Quero um site HTML estático simples, nada de frameworks.

Projeto: landing page para um corretor de imóveis (pessoa física). Nome fictício: Marina Alves Corretora.

Estilo visual (obrigatório):
- Institucional imobiliário contemporâneo
- Fundo off-white quente (#F7F4EF), texto azul-noite (#0B1F33), destaque em verde-musgo (#2F5D50)
- Título com fonte serifada; textos com sans-serif
- Hero full-bleed com sensação de imóvel/cidade (pode ser gradiente + formas; sem stock genérico de SaaS roxo)
- Sem cards com sombra pesada; layout limpo, respirado, uma ideia por seção

Conteúdo da página única:
1) Cabeçalho com nome e links (Início, Imóveis, Contato)
2) Hero com headline, uma frase de apoio e CTA WhatsApp
3) Seção "Imóveis em destaque" com 3 itens (título, bairro, preço fictício)
4) Seção curta "Sobre a corretora"
5) Rodapé com telefone e CRECI fictício

Crie HTML + CSS (JS só se for útil). Arquivos claros, caminhos relativos. Depois explique o que cada arquivo faz, em poucas frases. Evite complexidade.

Deixe a IA criar os arquivos. Depois, não aceite no automático. Abra cada arquivo, leia o HTML e o CSS, e abra o index.html no navegador (duplo clique ou um servidor local simples, se preferir).

Analisar o resultado

  • Existe um index.html na raiz?
  • O CSS está em arquivo separado ou embutido? Ambos servem; o importante é você achar.
  • Os caminhos são relativos (styles.css, não um caminho absoluto da máquina)?
  • O visual bate com o que você pediu, ou veio “template de SaaS”?

Rode git status e git diff se quiser ver o que apareceu. Grave um commit quando o esqueleto estiver ok:

Git

git add .
git commit -m "Estrutura inicial do site HTML"

Melhorar progressivamente

Agora peça uma melhoria por vez. Exemplos:

  • ajustar o texto do hero ou os 3 imóveis em destaque;
  • refinar cores e tipografia sem redesenhar tudo;
  • garantir que a página fica legível no celular.

Depois de cada mudança: abrir no navegador, ler o diff, só então o próximo pedido. O detalhe de como pedir alterações bem fica na próxima lição.

Sem Skills e sem SDD de propósito. Primeiro o ciclo curto. Métodos mais estruturados entram quando esse hábito já estiver natural.

Checklist

  • Pasta do projeto criada e aberta na ferramenta de IA.
  • Site abre no navegador a partir dos arquivos locais.
  • Você consegue apontar o que cada arquivo faz.
  • Há pelo menos um commit com a estrutura inicial.

Próximo passo

Com o site no ar localmente, a próxima lição treina o músculo mais usado no dia a dia: pedir alterações sem recontar o projeto inteiro.

Introduction

In this module you build real software, still without Skills and without SDD. The point is to feel the direct process: explain what you want, look at what the AI produced, ask for changes, and improve little by little.

The project is a static HTML site. It starts in an empty folder. It ends with files you open in the browser and understand.

What you will learn

  • How to open an empty project and ask for the initial structure.
  • How to review generated HTML, CSS, and (if any) JavaScript.
  • How to improve the site in small steps, without restarting everything.

Why this matters

If the first request is “build a complete professional site”, the AI delivers a big package and you lose the thread. A small site teaches the right habit: short scope, visible result, mandatory review.

Prepare the folder

In the terminal, inside ~/projetos (or the parent folder you already use):

Terminal

mkdir -p ~/projetos/meu-primeiro-site
cd ~/projetos/meu-primeiro-site
git init

Open that folder in Cursor, Claude Code, or the editor you chose. Confirm it is empty (only .git if you already initialized the repo).

The first request

State the context and the goal. Do not ask for the product of your life. Ask for a page you can understand.

Prompt

We are in an empty folder. I want a simple static HTML site, no frameworks.

Project: landing page for a real-estate broker (individual). Fictional name: Marina Alves Realty.

Visual style (required):
- Contemporary institutional real-estate look
- Warm off-white background (#F7F4EF), midnight-blue text (#0B1F33), moss-green accent (#2F5D50)
- Serif for headings; sans-serif for body
- Full-bleed hero with a sense of property/city (gradient + shapes is fine; no generic purple SaaS look)
- No heavy shadowed cards; clean, airy layout, one idea per section

Single-page content:
1) Header with name and links (Home, Listings, Contact)
2) Hero with headline, one supporting line, and WhatsApp CTA
3) "Featured listings" section with 3 items (title, neighborhood, fictional price)
4) Short "About the broker" section
5) Footer with phone and fictional license number

Create HTML + CSS (JS only if useful). Clear files, relative paths. Then explain what each file does, in a few sentences. Keep it simple.

Let the AI create the files. Then do not accept blindly. Open each file, read the HTML and CSS, and open index.html in the browser (double-click or a simple local server if you prefer).

Review the result

  • Is there an index.html at the root?
  • Is CSS in a separate file or inline? Both are fine; what matters is that you can find it.
  • Are paths relative (styles.css, not an absolute machine path)?
  • Does the look match what you asked, or did a “SaaS template” show up?

Run git status and git diff if you want to see what appeared. Commit when the skeleton looks ok:

Git

git add .
git commit -m "Initial HTML site structure"

Improve progressively

Now ask for one improvement at a time. Examples:

  • tweak the hero copy or the 3 featured listings;
  • adjust colors and type without redesigning everything;
  • make sure the page stays readable on a phone.

After each change: open in the browser, read the diff, only then the next request. How to ask for changes well is the next lesson.

No Skills and no SDD on purpose. First the short loop. More structured methods come when this habit already feels natural.

Checklist

  • Project folder created and open in your AI tool.
  • Site opens in the browser from local files.
  • You can point to what each file does.
  • There is at least one commit with the initial structure.

Next step

With the site running locally, the next lesson trains the muscle you use every day: asking for changes without retelling the whole project.
