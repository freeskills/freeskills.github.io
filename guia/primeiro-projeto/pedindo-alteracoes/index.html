How to ask the AI for changes Como pedir alterações para a IA

Change layout, copy, and responsiveness without retelling the whole project. Mude layout, textos e responsividade sem recontar o projeto inteiro.

Introdução

Você já tem um site HTML. O erro clássico agora é abrir um chat novo e descrever o projeto outra vez, como se a pasta não existisse. A IA perde contexto, você perde tempo, e as mudanças começam a brigar entre si.

Esta lição é sobre pedir alterações em cima do que já está no disco: layout, textos, seções, responsividade e correções pontuais.

O que você vai aprender

  • Como dar contexto sem recontar o projeto.
  • Como quebrar uma ideia grande em tarefas menores.
  • Como revisar cada mudança antes da próxima.

Por que isso importa

Desenvolver com IA é menos “gerar do zero” e mais “conversar com o código que já existe”. Quem domina pedidos de alteração consegue evoluir um site simples até ele ficar útil de verdade.

Regra de ouro

Trabalhe na pasta do projeto. Peça mudanças no que já está lá. Uma tarefa por mensagem, sempre que a mudança for visível.

Roteiro prático

Abra o projeto da lição anterior. Confirme no terminal que você está na pasta certa (pwd). Depois use um pedido como este:

Prompt

Continuamos no mesmo projeto HTML do site da corretora (não recomece do zero).

Mudanças, uma de cada vez:
1) Troque a headline do hero para algo mais direto sobre apartamentos na Zona Sul.
2) Adicione uma quarta seção "Depoimentos" com 2 frases curtas de clientes fictícios.
3) Melhore a responsividade: no celular, a lista de imóveis deve empilhar com boa leitura.
4) Corrija qualquer contraste fraco ou espaçamento estranho que aparecer.

Antes de editar, diga o que vai mudar. Depois de cada item, pare para eu revisar no navegador.

Observe o padrão: a IA não precisa do romance do site. Ela precisa saber que o projeto continua, o que muda, e quando parar.

Como dar contexto útil

  • Aponte arquivos quando souber: “só no styles.css”.
  • Descreva o sintoma: “no celular o texto corta”.
  • Diga o que não mudar: “não mexa no rodapé”.
  • Peça explicação curta se a mudança parecer grande demais.

Quebrar mudanças maiores

“Deixa o site mais profissional” é um pedido ruim. Transforme em fatias:

  1. 1Textos e hierarquia
  2. 2Espaçamento e tipografia
  3. 3Uma seção nova
  4. 4Ajuste mobile
  5. 5Correção de um bug visto

Entre uma fatia e outra: navegador + diff. Se algo estragar, peça para reverter só aquele pedaço, ou use o Git.

Pedido mínimo (quando já está no fluxo)

Prompt curto

Não refatore o projeto inteiro. Só: no CSS, aumente o espaçamento entre os itens da lista e deixe o hover dos links mais claro. Mostre o diff.

Checklist

  • Você pediu mudanças sem recriar o projeto.
  • Layout, seção, textos ou responsividade foram alterados de propósito.
  • Cada fatia foi vista no navegador antes da seguinte.
  • Há commits (ou pelo menos diffs claros) das melhorias.

Próximo passo

O site existe na sua máquina. Antes de hospedar, a próxima lição trata do nome que as pessoas vão digitar: o domínio.

Introduction

You already have an HTML site. The classic mistake now is opening a new chat and describing the project again, as if the folder did not exist. The AI loses context, you lose time, and changes start fighting each other.

This lesson is about asking for changes on top of what is already on disk: layout, copy, sections, responsiveness, and small fixes.

What you will learn

  • How to give context without retelling the project.
  • How to split a big idea into smaller tasks.
  • How to review each change before the next one.

Why this matters

Building with AI is less “generate from scratch” and more “talk to the code that already exists”. Whoever masters change requests can evolve a simple site until it becomes genuinely useful.

Golden rule

Work in the project folder. Ask for changes to what is already there. One task per message whenever the change is visible.

Practical walkthrough

Open the project from the previous lesson. Confirm in the terminal that you are in the right folder (pwd). Then use a request like this:

Prompt

We stay in the same HTML project for the broker site (do not start over).

Changes, one at a time:
1) Swap the hero headline to something more direct about apartments in the South Zone.
2) Add a fourth "Testimonials" section with 2 short fictional client quotes.
3) Improve responsiveness: on mobile, the listings list should stack and stay readable.
4) Fix any weak contrast or odd spacing that shows up.

Before editing, say what you will change. After each item, stop so I can review in the browser.

Notice the pattern: the AI does not need the novel of the site. It needs to know the project continues, what changes, and when to stop.

How to give useful context

  • Point to files when you know them: “only in styles.css”.
  • Describe the symptom: “on mobile the text gets cut off”.
  • Say what not to change: “do not touch the footer”.
  • Ask for a short explanation if the change looks too large.

Split larger changes

“Make the site more professional” is a bad request. Turn it into slices:

  1. 1Copy and hierarchy
  2. 2Spacing and typography
  3. 3One new section
  4. 4Mobile tweak
  5. 5Fix one bug you saw

Between slices: browser + diff. If something breaks, ask to revert only that piece, or use Git.

Minimal request (once you are in flow)

Short prompt

Do not refactor the whole project. Only: in the CSS, increase spacing between list items and make link hover clearer. Show the diff.

Checklist

  • You asked for changes without recreating the project.
  • Layout, section, copy, or responsiveness changed on purpose.
  • Each slice was checked in the browser before the next.
  • There are commits (or at least clear diffs) for the improvements.
